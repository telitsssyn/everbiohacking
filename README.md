# EverBiohacking

> Live longer. Think clearer. Feel better.

Билингвальный (RU + EN) сайт-база **живых протоколов** по биохакингу. Не лента статей, а набор документов, каждый из которых описывает, что автор делает прямо сейчас, и правится при каждом изменении: сон, питание, когнитивность, долголетие.

Автор и владелец: **Pavel**.

---

## 1. Цели проекта

1. Дать читателю одно надёжное место со структурированными, научно обоснованными протоколами по биохакингу.
2. Быть пожизненным проектом. Ценность растёт не от количества материалов, а от того, что каждый протокол поддерживается в актуальном состоянии. Единица работы — правка существующего протокола, а не выпуск новой статьи.
3. Заложить фундамент для будущих продуктов автора (EverPass — платная подписка, книга) без преждевременной реализации. Подписка продаёт актуальность протоколов, а не доступ к архиву.

**Ключевое следствие модели:** протокол обещает «так есть сейчас», а не «так было на дату публикации». Протокол, который не обновлялся год, хуже старой статьи — у статьи есть честная дата, у протокола нарушенное обещание. Дисциплина обновлений — условие работы модели, а не бонус.

---

## 2. Аудитория

Смешанная: и новички, и продвинутые энтузиасты. Различие уровней решается не отдельными рубриками, а **полем `level`** на протоколе (`beginner | intermediate | advanced`) и фильтром по нему в UI.

«For Beginners» на главной — это срез контента, не категория.

## 3. Скоуп MVP

### 3.1 Страницы
- **Main / Главная** — hero со слоганом, блок «About / Hi, I'm Pavel», секция «For Beginners» (3 материала), «Recently Updated» (что менялось последним), сетка «Topics» (10 рубрик), футер.
- **Protocols** — каталог всех протоколов; левый сайдбар с рубриками; вкладки `Recently Updated | Most Popular`.
- **Protocol page** — заголовок, две даты (обновлён / впервые опубликован), дисклеймер, hero-изображение, тело в MDX, опциональный видеоразбор, шаринг.
- **About** — расширенная страница про автора и проект.

### 3.2 Функциональные требования
- **i18n RU + EN** с самого старта. URL-сегмент языка (`/ru/...`, `/en/...`), переключатель в шапке. Контент локализуется попарно: каждый протокол — отдельный MDX-файл в `ru/` и `en/`, связанный через `translationKey`.
- **MDX** для контента: протоколы — это `.mdx` файлы в репо, версионируются в git. История правок протокола лежит в коммитах и на сайте не публикуется.
- **ISR** для страниц контента (обновление при ребилде / on-demand revalidate).
- **Server Components** по умолчанию; клиентские — только где нужны (фильтры, переключатель языка, форма подписки).
- **Тёмная тема** только, без переключателя.
- **Поиск** — иконка-лупа в шапке (placeholder в MVP, реализация на втором проходе при росте контента).
- **Редиректы** со старого URL-пространства `/articles/*` на `/protocols/*` (301) — постоянный URL это основная ценность протокола, накопленный вес терять нельзя.

### 3.3 Что НЕ делаем в MVP
- Авторизация, личные кабинеты, профили, дашборды.
- Платежи и платный контент (но архитектурно готовим место под paywall).
- Свой видеоплеер (только YouTube embed; видео — канал дистрибуции протокола, а не отдельный тип контента).
- Комментарии и UGC.
- Protocol Builder (конструктор протоколов пользователем), трекеры биомаркеров — не запланированы. Протоколы на сайте авторские и редактируются в MDX.

### 3.4 Заглушки
- Кнопка **«Get EverPass»** в шапке → страница `/everpass` с «Coming soon».
- Кнопка **«Buy my book»** в шапке → страница `/book` с «Coming soon».

Каждая рубрика — отдельная посадочная страница `/protocols/[section]` со списком своих протоколов.

**Гранулярность:** рубрика ≠ протокол. Один раздел содержит несколько протоколов под конкретные задачи («Циркадный сброс», «Восстановление после недосыпа», «Джетлаг»), а не один документ на всю тему. Иначе сайт схлопывается в 10 страниц на локаль и теряет охват запросов.

## 5. Модель контента (frontmatter MDX)

```yaml
---
title: "How I Optimized My Sleep"
slug: "how-i-optimized-my-sleep"    # постоянный, без года и без «v2»
lang: "en"                          # en | ru — может выводиться из папки
section: "sleep"                    # один из 10 slug'ов рубрик
topics: ["circadian", "recovery"]   # свободные теги, кросс-рубричные

type: "protocol"                    # единственный тип контента

date: "2026-05-08"                  # первая публикация, больше не меняется
updated: "2026-05-08"               # последняя правка — задаёт сортировку
lastReviewed: "2026-05-08"          # последняя сверка; в данных есть, в UI не выводится

videoUrl: null                      # YouTube-разбор протокола, опционально
excerpt: "Quality sleep is the single highest-leverage habit I've found..."
heroImage: "/images/sleep-hero.png"
readingTime: 5                      # минут, можно считать автоматически
draft: false
featured: false                     # выводится в блоке For Beginners
---
```

**Две даты — весь сигнал актуальности.** `date` фиксирует происхождение, `updated` — обещание «так есть сейчас» (по нему идёт сортировка везде). Ничего сверх этого читателю не нужно: он приходит убедиться, что протокол не протух, и дата отвечает на это сразу. Номера версий и публичная история правок сознательно не выводятся — их никто не читает, а сигнал они дублируют. `lastReviewed` остаётся в данных, но на страницу не выводится.

### MDX-компоненты (доступны внутри `.mdx`)
- `<Callout>` / `<TLDR>` — выделенные блоки с ключевым выводом.
- `<ProtocolSummary>` — блок «что делать» в начале протокола: пары «параметр — значение». Читатель, которому нужны только текущие инструкции, должен иметь возможность остановиться здесь.
- `<DosageTable>` — таблица дозировок (актуально для БАДов).
- `<References>` — список первоисточников / исследований.
- `<MedicalDisclaimer>` — медицинский дисклеймер; на страницах протоколов выводится автоматически в шапке.
- `<YouTube>` — embed видео внутри тела протокола.

## 6. Визуальный язык

- **Цвет:** чистый чёрный фон (`#000` / near-black), белый/серый текст, минимум акцентов.
- **Типографика:** заголовки — **Roboto Serif** (display); тело — **Inter** (sans). Подключение через `next/font/google`.
- **Сетка:** широкие поля, много воздуха, центрированная контентная колонка для лонгридов.
- **Иллюстрации:** ч/б в едином стиле, как на макетах (карточки протоколов, hero).
- **Кнопки:** скругление 9999px (pill), тонкая обводка для secondary, заливка для primary.

## 7. Дорожная карта

### v0.1 — MVP (этот цикл)
4 страницы, i18n, MDX-контент, дизайн по макетам, заглушки EverPass / Book / Newsletter.

### v0.1.1 — переход на протоколы
Контент-модель `article | video` заменена на единый `protocol` с датами `date` / `updated`. Маршруты `/articles/*` → `/protocols/*` с 301-редиректами.

### v0.2 — EverPass (платная подписка)
- Magic-link auth через Supabase (email = identity, без паролей).
- Stripe Checkout с пробным периодом.
- Гейтинг отдельных протоколов (поле `access: free | pass` во frontmatter). Подписка продаёт актуальность протоколов, а не разовый доступ к тексту.

### v0.3 — Book
- Продажа PDF-книги через Stripe Checkout.
- Доставка ссылки на скачивание через transactional email (Resend / Postmark).

### v0.4 — Newsletter
- Реальная рассылка через Resend / Postmark.
- Double opt-in для формы в футере.

### v0.5+ — поиск, аналитика, оптимизации
- Полноценный поиск по контенту (например, Algolia или локальный индекс).
- Аналитика без cookie (Plausible / Vercel Analytics).
- Open Graph / sitemap / RSS.
